### 1.2 UX 問題（「第一眼看不出能做什麼」）

1. 沒有上傳入口，一進站自動載 Demo。
2. 4 個 tab 中 2 個是行銷素材（NotebookLM 對照、簡報心智圖），與核心工具平級，主線被稀釋。

6. `MultiVersionTimeline` 全是寫死假資料，卻無「示範資料」標記，Demo Day 有誤導風險。

## 2. 設計主張：對話式 Agent 三欄

不用步驟精靈，改成**以對話為主軸的 agent 介面**——引導感來自 agent 主動敘事 + 建議動作 chips，而不是強制的線性步驟。

```
┌──────────────────────────────────────────────────────────────────────┐
│ TopBar   Plimsoll · 文件對 pill ······ [收左欄] [收右欄] [⚙️ 設定]     │
├────────────┬──────────────────────────────────┬──────────────────────┤
│ 對話紀錄    │        對話主區（中）              │  來源 ｜ 原文（右）   │
│ (可收合)    │  · agent 訊息 + 富卡片            │  · 本機資料夾／Drive  │
│ + 新的比對  │  · KPI 卡 / 差異卡（可就地覆核）    │  · 舊版／新版丟檔槽   │
│ 排序 · 拖曳 │  · 建議動作 chips                 │  · 原文頁 + 高亮命中  │
│ 本機/遠端tag│  ┌ composer 輸入框 ┐              ├──────────────────────┤
│            │                                  │  ● 流程節點（固定底部）│
└────────────┴──────────────────────────────────┴──────────────────────┘
```

四個原則：

- **對話是主線**：agent 每完成一件事就用一則訊息交代結果 + 給下一步建議 chips（「開始逐項覆核」「只看 4 筆 High」「先匯出報告」），使用者永遠知道能做什麼。
- **工作發生在對話裡**：差異卡直接展開就能判定（不用跳頁），保留完整 diff 對照與覆核控制。
- **右欄是證據**：點任何頁碼，右欄切到「原文」並跳到該頁、高亮命中句——這是「100% 可追溯」的視覺證據，取代第一版的雙欄 PDF viewer。
- **狀態在右下角，不在頂部**：流程節點固定在右欄底部（載入來源 → 差異比對 → 逐項覆核 → 簽核匯出），取代頂部步驟列；右欄收合後仍保留節點小圓點。

TopBar 只留品牌、文件對、雙欄收合鈕與齒輪。**角色、主題、語言、字型、高亮色、背景、API Key、資料來源全部收進設定齒輪**。

## 3. 三欄規格

### 3.1 左欄 `HistoryRail`（238px，可收合至 50px）

| 元件 | 規格 |
|---|---|
| `NewComparisonButton` | 黑底實心，開新的比對工作階段 |
| `HistorySearch` | 搜尋比對紀錄 |
| `SortBar` | **排序下拉**（最近更新／建立時間／名稱 A→Z／High 風險數／手動排序）＋ 升降冪切換鈕 |
| `HistoryList` | 依「今天 / 前 7 天 / 更早」分組。每列：拖曳握把、標題、`v1.0→v1.1`、差異數、High 數，**外加儲存位置 tag** |
| `UserFooter` | 頭像 + 姓名 + 角色 |
| 收合態 | 只留「＋」「展開」「紀錄」三顆圖示 + 頭像 |

**排序與拖曳**
- 條件排序：下拉選單選欄位，右側小鈕切換升／降冪，選擇存 `localStorage`。
- 手動排序：下拉選「手動排序」後，每列左側握把可拖曳（hover 才顯示，避免視覺噪音），拖曳中顯示插入位置指示線，來源列半透明並加虛線外框。
- 手動順序**只影響左欄顯示**，不動資料本身；切回條件排序時保留手動順序，可隨時切回。
- 實作用 HTML5 drag-and-drop 或 `@dnd-kit`；觸控裝置改為長按 400ms 觸發拖曳。

**儲存位置 tag（四種）**

| tag | 樣式 | 意義 |
|---|---|---|
| `本機` | 白底細框 | 只存在這台瀏覽器的 `localStorage`，不含 PDF 原檔 |
| `遠端` | 黑底白字 | 已寫入後端，含 PDF 原檔暫存，可跨裝置開啟 |
| `未同步` | 琥珀底 | 有本機變更尚未上傳（覆核狀態改過但沒同步） |
| `Drive` | 白底深框 | 來源檔案來自 Google 雲端硬碟（用在來源卡，非工作階段） |

- `本機` / `未同步` 項目 hover 出現「同步到伺服器」動作。
- 列表頂端在有本機項目時提示「N 筆比對僅存在本機，清除瀏覽器資料會消失」。
- tag 同時出現在：左欄每列、對話標題列、右欄流程狀態列表頭。
- 後端需求見 §5 B7。

### 3.2 中欄 `ConversationThread`

**`ThreadHeader`**：工作階段標題、狀態 pill、儲存位置 tag。**覆核進度不放這裡** —— 移到右欄底部的流程節點（見 §3.3）。

**`Thread`** 訊息型別：

| 型別 | 內容 |
|---|---|
| `text` | 一般 agent／使用者訊息 |
| `doc-info` | 文件資訊卡（兩份文件的標題、版本、日期、頁數、文字層品質） |
| `alert` | 缺件警示 / 掃描頁警示 / 未覆核 High 警示 |
| `overview` | KPI 四格（總差異／High／已覆核／待簽核 High）＋風險分佈條＋受影響設備 |
| `diff-list` | 差異卡列表，每張可展開 |
| `diff-detail` | 展開態：雙欄逐字 diff → 讀出區 → 覆核判定列 |
| `export` | 簽核資訊表單 + 匯出格式 |
| `actions` | 建議動作 chips（永遠附在訊息尾端） |

**`DiffCard`（核心元件）**

- 收合態：風險 pill／變更類型／信心度／ID、一句話標題、**數值前後對照**（`85 °C` → `80 °C`）、受影響設備、`舊 p.4 → 新 p.4`（可點）
- 展開態：
  - 雙欄原文，**逐字級 diff**：`<del>` 紅刪除線 / `<ins>` 綠加粗
  - 讀出區：變更解讀、**觸發規則**（數值變更 / 安全關鍵詞 / 義務詞彙 — 讓風險分級可解釋）、建議處置
  - `ReviewBar`：三選一判定（已確認／需追蹤／不採納）＋**風險改判下拉**（人工覆蓋 AI 初判）＋覆核筆記＋「確認並前往下一筆」
  - 鍵盤：`J`/`K` 上下筆、`A`/`T`/`D` 判定、`Enter` 確認並跳下一筆

**`Composer`**：多行輸入、附件鈕（等同丟檔）、引用鈕（把目前差異帶入提問，顯示「已引用 D01」）、模型名稱、送出。上方為建議問題 chips，下方常駐免責聲明一行。RAG 回答**必須附 `D01 · 新 p.4` 形式的引用 pill**，點擊跳右欄對應頁。

### 3.3 右欄 `SidePanel`（344px，可收合至 46px）

兩個分頁 + 底部固定的流程節點。

**分頁一「來源」**
- **來源連線入口**（新增）：
  | 入口 | 實作 | tag |
  |---|---|---|
  | 選擇本機資料夾 | File System Access API（`showDirectoryPicker`），不支援的瀏覽器降級為 `<input webkitdirectory>` | `本機` |
  | 連結 Google 雲端資料夾 | Google Picker + Drive API **唯讀** scope（`drive.readonly` 或 `drive.file`），只讀取使用者指定的資料夾 | `Drive` |
  - 兩者都只列出資料夾內的 PDF，並提供搜尋與「指定為舊版／新版」動作
  - 明示「Plimsoll 只讀取你指定的資料夾，不會掃描其他位置」
- 空狀態：舊版 / 新版兩個 `Dropzone`（拖曳或點選，僅收 PDF）＋「開始版本差異比對」（未齊全時 disabled）
- 已載入：`FileCard` — 檔名、**來源 tag**、頁數（實際值）、大小、文字層品質、版本、日期、移除鈕
- **`MissingVersionField`**：版本號抓不到時就地補填，未填妥 → 比對按鈕維持 disabled（**系統不自行猜測版本號**）

**分頁二「原文」** — 兩種呈現模式可切換

| 模式 | 說明 |
|---|---|
| **文字重建（預設）** | 用 `extract_pages()` 抽出的文字重排該頁。可高亮命中句（`mark.hit`）、可搜尋、可點擊跳轉。這是「100% 可追溯」最有說服力的呈現。 |
| **原始 PDF** | `<embed src="/api/pdf/{side}#page=n">` 嵌入原檔。排版 100% 忠實，但瀏覽器內建檢視器無法高亮特定句子，改在頁面上方以文字列出「本頁命中：…」。 |

- 兩種模式在分頁上方以分段控制切換，預設「文字重建」，選擇記憶在 `localStorage`。
- 共通：舊版 / 新版 / 並排 三態、上下頁、「4 / 6 · 命中 2 處」。
- 「原始 PDF」模式需要後端暫存原檔（§5 B3）；`本機` 未同步的比對紀錄無 PDF 原檔時，此模式顯示「原檔未保存，請重新上傳或同步到伺服器」。

**底部固定 `FlowNodes`（流程節點）**

取代原本頂部的步驟列。直式四節點，永遠可見：

| 節點 | 狀態與副標 |
|---|---|
| 載入來源 | `v1.0 → v1.1 · 各 6 頁` ／ 待補件時轉紅 |
| 差異比對 | `25 筆 · 4 High · 8.2 秒` |
| 逐項覆核 | `18 / 25 已判定 · 2 High 待判` + 細進度條（綠＝已判、紅＝High 未判） |
| 簽核匯出 | `2 項 High 未覆核，將標為修訂草稿`（紅色警示態） |

- 四種節點狀態：`未開始`（灰）／`進行中`（黑，帶光暈）／`已完成`（綠勾）／`警示`（紅驚嘆）
- 節點可點擊，跳到對話中對應的訊息位置
- 表頭右側顯示該工作階段的儲存位置 tag
- **右欄收合至 46px 後，流程節點縮成一排小圓點**（保留顏色狀態），不必展開就知道進度
- 匯出前檢核清單與匯出格式改放在「來源」分頁下方（有結果時才出現）

### 3.4 `SettingsPanel`（右上齒輪）

**所有全域設定都在這裡**，桌面為 392px 浮層、手機為全螢幕頁。分五個分頁：

**① 一般**
| 區塊 | 內容 |
|---|---|
| 介面語言 | 繁體中文 / English |
| 外觀 | 淺色 / 深色 / 跟隨系統 |
| 自訂背景 | 預設 / 純色 / 漸層 / 紋理 / 上傳圖片 + 模糊與遮罩滑桿。**只套用在畫布層**，卡片、文字與風險色不受影響，確保對比度 |
| 預設儲存位置 | 僅本機 / 自動同步到伺服器 |

**② 角色**（見 §3.5）

**③ AI 模型**
| 區塊 | 內容 |
|---|---|
| 分析模型 | Bedrock Claude 3.5 / OpenAI GPT-4o / Gemini / Groq / **不使用 LLM（本機規則引擎）** |
| **API Key / Token** | 密碼型輸入 + 「套用」。**狀態列**顯示「已啟用 XX LLM 模式」（綠燈）或「未設定，使用本機精準規則引擎」（灰燈）—— 這是第一版有、現行 React 版遺失的 F5。Key 只存瀏覽器工作階段，不寫入原始碼或版控 |
| 推論參數 | 唯讀顯示 `Temperature 0.5 / Top P 0.95 / Top K 40 / Repeat Penalty 1.1`（依工作包 S1000D 事實對齊規範） |

**④ 資料來源**
- 本機資料夾：顯示已授權路徑，可更換／移除
- Google 雲端硬碟：顯示已連線帳號與資料夾，可中斷授權
- 明示唯讀權限範圍

**⑤ 更多視圖**
- 多版本演進矩陣、簡報與心智圖、與 NotebookLM 的差異（皆接真實資料，見 §5 B9）

齒輪未設定 Key 時顯示提示小紅點。所有偏好存 `localStorage`。

### 3.5 角色（設定 → 角色）

**角色從 TopBar 移進設定**，因為它不是高頻操作，放在頂部只會佔用視覺權重。不再整頁替換 dashboard（那正是功能被藏起來的原因）。角色只影響：

| | 安品主管 | 維修工程師 |
|---|---|---|
| 進站預設 | 總覽 KPI + 未覆核 High 摘要 | 直接進逐項覆核 |
| 差異排序 | 風險 × 未覆核優先 | 依文件頁序 |
| 右欄預設分頁 | 來源（含檢核清單） | 原文 |
| 匯出區 | 顯示簽核欄位 | 摺疊 |

**功能集合完全相同**，兩個角色都能存取全部能力。

## 4. 視覺系統

**原則：全站中性灰階、零色偏（Twenty 風格）。強調色就是黑（深色模式即白），沒有品牌彩色。**

唯一保留的彩色是**風險語意色**——High / Medium / Low 是命題明文要求的工安標示（「重大變更須以紅色高亮標示」），純黑白會讓這個核心價值消失。因此保留，但降飽和成 muted 色，且**只出現在**風險 pill、數值前後對照、警示框、覆核狀態這四種地方。

| 主題實作 | CSS 變數 + `document.documentElement[data-theme]`；「跟隨系統」用 `prefers-color-scheme` media query；選擇存 `localStorage`；`color-scheme` 一併設定讓原生控制項跟著切換 |
| 無障礙 | 風險不只用顏色（同時有文字 pill）；焦點環 `0 0 0 3px accent-soft`；主要文字對比 ≥ 4.5:1，深色模式需重新驗證每個風險色 |
